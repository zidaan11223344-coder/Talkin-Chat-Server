# سيرفر إدخال بوتات Talkin — S-Boot

خدمة مستقلة لمنصة **Talkin/ChatP** لإضافة حسابات بوت متحكمة أو صامتة من خلال حساب السيرفر `-sbot-` في الخاص. استُخدم عميل البروتوكول من مستودع `Talkin2` الذي حددته، لكن هذه الخدمة تفصل إدارة الإدخال عن البوت الشامل وتسمح فقط بالنطاق المطلوب.

> **نطاق البوت المتحكم:** الإدارة والحماية والدعوات والقوائم، بالإضافة إلى لعبة كركيت اختيارية مشتركة بين غرف البوتات المتحكمة. لا يشغّل أغاني أو نشرًا أو أوامر عامة أخرى.

## حالة البروفايل

### حساب السيرفر الأساسي `-sbot-`

يضع السيرفر الحالة الملونة الظاهرة في المرجع:

- `🛡️ -sbot-` — أحمر
- `سيرفر إدخال بوتات تحكم وصامتة` — بنفسجي
- `الإدارة • الحماية • الدعوات • القوائم` — أخضر
- `Bot Entry Server • Admin • Protection • Invites • Lists` — **أزرق** بدل الأصفر

### البوتات المدخلة

عند الاتصال، تُحدَّث الحالة الملونة تلقائيًا إلى:

```text
🤖 بوت متحكم / بوت صامت
👑 ادمن السيرفر: ۦاݪــۛـسـ𓆩♛𓆪ـۧۦـ۫ـفـيــ۫ـۧ𝁤𝆬𝃛
🏠 الغرفة: اسم الغرفة
👑 الماستر: اسم من أضاف البوت
```

لا تُعدّل الخدمة صورة الحساب؛ تبقى صورة البروفايل الأصلية كما هي. بروتوكول Talkin المتوفر يوفّر تحديث حالة نصية موثوقًا، وليس واجهة موثوقة لتغيير الصورة.

## قبول الصداقة والترحيب

لا يحتاج قبول الصداقة إلى Supabase أو مفاتيح قاعدة بيانات. يستخدم السيرفر أوامر Talkin الأصلية التي يستخدمها التطبيق نفسه: يطلب قائمة الطلبات عبر `profile_update / send_requests`، ثم يقبل كل طلب عبر `profile_update / accept_friend` باسم المستخدم.

بعد قبول الطلب يرسل تلقائيًا:

```text
مرحبا بك في سيرفر بوتات s-boot

لاختيار العربية أرسل 1
لاختيار الإنجليزية أرسل 2
```

يحفظ الاختيار لكل مستخدم داخل ملف الحالة الدائم.

## أوامر حساب السيرفر في الخاص

| الأمر | الوظيفة |
|---|---|
| `اسم_البوت@كلمة_المرور@اسم_الغرفة` | إضافة بوت متحكم. أول شخص يضيف بوتًا للغرفة يصبح الماستر الأساسي. |
| `hb@اسم_البوت@كلمة_المرور@اسم_الغرفة` | إضافة بوت صامت. |
| `بوتصامت@...` أو `صامت@...` | بديل عربي لإضافة البوت الصامت. |
| `bots` | عرض البوتات التي تتحكم بها. |
| `room@اسم_الغرفة` | حالة بوتات الغرفة. |
| `del@اسم_الغرفة` | حذف البوت المتحكم فقط. |
| `delall@اسم_الغرفة` أو `clean@اسم_الغرفة` | حذف كل بوتات الغرفة. |
| `master@اسم_المستخدم@اسم_الغرفة` | إضافة ماستر مساعد — للماستر الأساسي فقط. |
| `delmaster@اسم_المستخدم@اسم_الغرفة` | حذف ماستر مساعد. |
| `mas@اسم_المستخدم@اسم_الغرفة` أو `mas@اسم_المستخدم` | اختصار إضافة ماستر مساعد؛ يمكن حذف اسم الغرفة إذا كانت لديك غرفة واحدة فقط. |
| `umas@اسم_المستخدم@اسم_الغرفة` أو `umas@اسم_المستخدم` | اختصار إزالة ماستر مساعد. |
| `masters@اسم_الغرفة` | عرض الماسترات. |
| `lang@ar` أو `lang@en` | تغيير لغة رسائل حساب السيرفر. |

> لا تُرسل كلمات مرور البوتات في الغرف العامة؛ أرسلها لحساب `-sbot-` في الخاص فقط. تحفظ الخدمة كلمات المرور **مشفّرة** داخل مجلد البيانات الدائم.

## أوامر البوت المتحكم داخل غرفته

| المجال | الأوامر |
|---|---|
| الإدارة | `k@اسم` أو `kick اسم` طرد، `b@اسم` أو `ban اسم` حظر، `bl@اسم` حظر بكل غرف السيرفر، `ub@اسم` أو `u@اسم` أو `unban اسم` فك الحظر، `m@اسم` منح عضوية، `.u` تراجع عن آخر إجراء إداري مؤكد. |
| الحماية | `حماية`، `تشغيل الحماية`، `إيقاف الحماية`، `+mf@كلمة`، `-mf@كلمة`، `l@mf`، `clear@mf`، `mr@3`. |
| الدعوات | `inv` يجمع الأونرات والمشرفين والأعضاء ثم يرسل الدعوات، `invmsg@نص الدعوة` يغيّر النص لهذه الغرفة ويحافظ على اسمها بين قوسين، و`invmsg@reset` يعيد الافتراضي. يمكن استخدام `{room}` و`{username}` و`{sender}` داخل النص. |
| القوائم | `l@m` للأعضاء، `l@a` للمشرفين، `l@o` للأونرات، `l@b` للمحظورين، `l@all` للكل، `l@mas` للماسترات، و`l@inv` لعرض المدعوين برسالة واحدة. إذا تجاوزت الأسماء حد رسالة Talkin، تظهر الأسماء التي تتسع لها الرسالة مع الإجمالي وعدد الأسماء غير المعروضة. |

تظهر المساعدة على صفحتين منظمتين؛ أرسل `help` ثم `ns` للقائمة التالية. يمكن طلبها داخل الغرفة أو في الخاص. تعرض `l@mas` و`l@inv` النتائج في المحادثة التي استقبلت الأمر.

يشترط تشغيل البوت المتحكم أن تكون رتبته **أونر** في الغرفة. إذا كانت رتبته أقل، يغادر البوت ويرسل للماستر: «ارفع البوت أونر ثم أعد المحاولة». وإذا طُرد البوت من الغرفة، يحاول الانضمام إليها تلقائيًا؛ أما أمر الخروج المقصود فلا يؤدي إلى إعادة الانضمام.

### الدعوات ورسالة الدعوة

يجمع `inv` القوائم الحية من Talkin بالترتيب: `owners_list` ثم `admins_list` ثم `members_list`، ولا يبدأ إرسال أي دعوة قبل اكتمالها. بعد ذلك يزيل التكرار والبوت نفسه ويرسل دعوة خاصة لكل مستخدم. صُحّح ترتيب معالجة الردود حتى لا يبدأ البوت من أول فئة ويهمل بقية القوائم.

لتغيير الدعوة في غرفة معينة، أرسل مثلًا `invmsg@أهلًا بك، انضم إلينا`. يضيف النظام تلقائيًا `({room})` إذا لم تضع `{room}` بنفسك؛ بذلك يبقى اسم الغرفة ظاهرًا مع تغيّر الرسالة فقط. الأمر `l@invmsg` يعرض الرسالة المحفوظة ومعاينتها.

### لعبة الكركيت بين الغرف

- فعّل اللعبة مرة واحدة من أي غرفة متحكمة: `.cr 1`؛ يصبح بإمكان بقية غرف البوتات المتحكمة الانضمام. أوقفها من أي غرفة: `.cr 0`.
- في أول غرفة ابدأ `كركيت 2` أو `cricket 2` لانتظار غرفتين؛ ويمكن اختيار 2–8 غرف.
- من كل غرفة أخرى مفعّلة أرسل `join`. بعد اكتمال العدد تختار كل غرفة `1` للهجوم أو `2` للدفاع؛ يجب أن يوجد فريق من كل نوع.
- بعد البدء يرسل الضارب رقمًا من `0` إلى `6`، ويخمّن الفريق الآخر رقمًا من المجال نفسه. تطابق الرقمين يخرج لاعبًا؛ عدم التطابق يضيف نقاط رقم الهجوم. لكل شوط ست كرات وثلاثة ويكيت، ثم يتبادل الفريقان الهجوم والدفاع.
- الخروج في أول كرة يعطي **دَك**، وثلاثة ويكيت متتالية تعطي **هاتريك**. تشارك البوتات حالة المباراة عبر مجلد البيانات نفسه، وتعرض صور الكرات الست وصور الدَك والهاتريك.
- جميع الصور PNG شفافة وأقل من `100 KB` لكل صورة. تُحمّل افتراضيًا من مجلد `vendor/assets` في المستودع؛ يمكن تغيير رابط الصور عبر `CRICKET_ASSET_BASE_URL`.

## الإعداد والنشر

1. اضبط بيانات حساب السيرفر في `SERVER_BOT_ID` و`SERVER_BOT_PASSWORD`، واربط مجلد بيانات دائمًا قابلًا للكتابة.
2. عند أول تشغيل، ينشئ التطبيق مجلد البيانات ومفتاح التشفير تلقائيًا داخل `BOT_SERVER_DATA_DIR/.state_encryption_key`. في التشغيلات التالية يعيد استخدام المفتاح نفسه؛ **لا تحذف مجلد البيانات ولا ملف المفتاح** حتى لا تفقد القدرة على فك كلمات مرور البوتات المخزنة.

   إذا كانت المنصة مثل RavenHost تجعل `/data` للقراءة فقط، غيّر `BOT_SERVER_DATA_DIR` إلى مجلد البيانات الدائم القابل للكتابة الذي توفره المنصة (أو `./data` إذا كان مجلد المشروع قابلًا للكتابة). **يجب أن تشترك كل عمليات البوتات في هذا المجلد** حتى تعمل اللعبة والأوامر الشاملة. إذا حددت `STATE_ENCRYPTION_KEY` يدويًا، فسيستخدمه التطبيق بدل إنشاء الملف.

3. عيّن على الأقل:

   ```env
   SERVER_BOT_ID=-sbot-
   SERVER_BOT_PASSWORD=كلمة_مرور_حساب_السيرفر
   # اترك STATE_ENCRYPTION_KEY غير محدد كي يتم توليده عند أول تشغيل
   BOT_SERVER_DATA_DIR=./data
   ```

4. للنشر عبر Docker اربط مجلد بيانات دائمًا على `/data`، واجعل متغير `BOT_SERVER_DATA_DIR=/data`؛ مثال التشغيل المحلي:

   ```bash
   docker build -t talkin-sboot .
   docker run --env-file .env -e BOT_SERVER_DATA_DIR=/data -p 8080:8080 -v talkin-sboot-data:/data talkin-sboot
   ```

5. تحقق من الخدمة:

   ```bash
   curl http://localhost:8080/health
   ```

لا توجد أي متغيرات Supabase مطلوبة لقبول الصداقة؛ قبول الطلبات يتم على اتصال Talkin الخاص بالحساب الأساسي.

## بنية المشروع

```text
app.py                 تشغيل الحساب الأساسي + HTTP health endpoint
control_server.py      أوامر الإدخال وإدارة العمليات التابعة
control_runtime.py     استقبال الأوامر الخاصة لحساب S-Boot
restricted_runtime.py  البوت المتحكم/الصامت المقيد بالوظائف المطلوبة
cricket_game.py        حالة مباراة الكركيت المشتركة بين الغرف
invite_templates.py    نصوص دعوة مستقلة ومحفوظة لكل غرفة
room_actions.py        طابور مشترك لأوامر bl@
runner.py              مشغل كل بوت تابع
registry.py            سجل البوتات والماسترات والصلاحيات
state.py               تخزين JSON ذري وتشفير كلمات المرور
friendships.py         قبول الصداقة والترحيب التلقائي
generate_key.py        توليد مفتاح STATE_ENCRYPTION_KEY
vendor/talkin_runtime.py  عميل Talkin من Talkin2
vendor/assets/           صور الكرات والدَك والهاتريك (<100 KB للصورة)
```

## نقطة الصحة

- `GET /health`
- `GET /status`

تعرض عدد البوتات الفعالة والمتصلة، ولا تكشف كلمات المرور أو مفاتيح البيئة.
